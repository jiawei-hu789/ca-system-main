# CA系统两人分工方案

版本：第三版（统一用户申请，与后端实现同步）

编制日期：2026年10月26日  
课程设计周期：2026年10月26日至11月6日  
分工方式：同学A负责前端，同学B负责后端。姓名待组内填写。

## 1 项目目标与完成范围

完成一个具备申请人端和CA管理员端的证书管理系统，实现用户生成密钥对、提交认证申请和证明材料、管理员审核、签发证书、查询证书与吊销证书的完整流程。

本版采用统一的“用户申请”流程：用户填写姓名、邮箱，提交公钥和证明材料。申请表、审核流程、数据库和接口均不设置个人／组织分类，也不要求填写单位名称。普通用户与CA管理员仍是两种操作角色，用于区分申请和审核权限。

任务书中提到的证书、营业执照扫描文档，是认证过程中保存的证明材料示例，不表示必须支持多种数字证书格式或分别建设多类申请流程。

本方案按照两人、两周的工作量安排。先完成必做功能，再根据剩余时间增加拓展功能。

截至2026年10月27日，后端主要接口已实现；前端仍需接入业务。最新字段和返回内容以[接口约定](接口约定.md)及[OpenAPI定义](openapi.yaml)为准。

下表是本项目基础版的开发范围，其中登录、角色控制、验证页面和操作记录用于支撑完整演示与安全管理，属于方案设计，并非任务书逐项指定的功能。

### 1.1 必做功能

| 编号 | 功能 | 完成标准 |
| --- | --- | --- |
| F01 | 用户登录与角色区分 | 普通用户和管理员登录后进入对应页面，后端校验访问权限 |
| F02 | 用户生成密钥对 | 用户在浏览器本地生成密钥对，公钥用于提交申请，私钥由用户加密保存 |
| F03 | 认证申请 | 提交申请人信息、公钥和证明材料，生成可查询的申请记录 |

| F05 | 申请审核 | 管理员查看资料，选择通过或驳回，记录审核意见、操作人和时间 |
| F06 | 证书签发 | 审核通过后，由CA签发真实的X.509 v3证书，证书序列号唯一 |
| F07 | 证书查询与下载 | 用户查询本人证书并下载证书文件，页面显示有效期和状态 |

### 1.2 拓展功能

在必做功能完成并通过联调后，再考虑以下内容：

1. 导出由CA签名的证书吊销列表CRL，方便外部程序检查吊销状态。
2. 增加申请签名或挑战签名验证，证明申请人持有所提交公钥对应的私钥。
3. 使用用户私钥对示例文件签名，再通过用户证书验证签名。

## 2 技术选型

采用浏览器前端与Java后端分离的结构。开发时前后端分别启动；最终将前端构建文件交由后端提供访问，方便在一台电脑上演示。

任务书要求能够签发和吊销证书，未指定证书标准或要求支持多种格式。本方案建议统一采用X.509 v3作为实现格式；这是技术选型，不是任务书规定。基础版按一种证书格式开发。

| 部分 | 技术 | 具体用途 |
| --- | --- | --- |
| 前端框架 | Vue 3 + Vite | 用户页面、管理员页面、页面路由和交互 |
| 前端语言 | JavaScript、HTML、CSS | 页面实现与浏览器端密钥处理 |
| 页面组件 | Element Plus | 表单、表格、上传、对话框和状态提示 |
| 网络请求 | Axios | 调用后端接口、上传材料和下载文件 |
| 用户密钥生成 | 浏览器Web Crypto API | 本地生成密钥对、加密保存用户私钥 |
| 后端语言 | Java 17 | 业务逻辑、权限处理和密码库调用 |
| 后端框架 | Spring Boot + Spring MVC | REST接口、登录会话和文件上传 |
| 身份与权限 | Spring Security + Session | 登录、用户与管理员角色控制、CSRF防护 |
| 数据访问 | Spring JDBC / JdbcTemplate | 执行SQL并处理数据库事务 |
| 数据库 | SQLite + sqlite-jdbc | 保存用户、申请、加密材料、证书及吊销记录 |
| 证书库 | Bouncy Castle的bcprov和bcpkix | 生成和签名X.509证书，可拓展CRL导出 |
| CA密钥保存 | Java PKCS#12 KeyStore | 保存CA私钥与CA证书，使用口令保护 |
| 构建管理 | npm、Maven | 管理依赖并生成可运行交付文件 |

前后端第一天统一具体依赖版本，将版本写入各自配置文件并提交锁文件。Bouncy Castle相关依赖采用相同版本。

### 2.1 密钥和证书约定

- 用户密钥采用RSA 2048位，签名算法采用SHA-256与RSA。
- 浏览器只提交公钥，建议使用PEM编码的SPKI公钥，后端负责解析和检查格式。
- 用户私钥通过浏览器端口令派生与认证加密后下载保存；文件中记录恢复所需的算法参数。私钥保存格式在开发前统一说明。
- 用户私钥及其保护口令不发送给后端，也不写入后端日志。
- CA私钥由后端保管，保护口令通过运行配置或启动输入提供。
- 按本方案建议，用户证书统一采用X.509 v3格式，至少包含序列号、颁发者、使用者、公钥、有效期和CA签名；使用者信息取自统一申请表，姓名可映射到证书的CN字段。
- 根CA证书设置CA属性，用户证书设置为非CA证书，并配置与演示用途相符的密钥用途。
- 密钥生成和证书处理调用成熟密码库，避免自行编写RSA等密码算法。

浏览器端密码操作在localhost或HTTPS环境中运行。演示优先使用localhost，使用其他电脑访问时一并配置HTTPS。

### 5.1 申请提交字段

提交类型采用`multipart/form-data`，字段至少包括：

| 字段 | 含义 | 约定 |
| --- | --- | --- |
| `applicantName` | 申请人姓名 | 必填 |
| `email` | 联系邮箱 | 必填，检查格式 |
| `publicKeyPem` | 用户公钥 | PEM编码的SPKI公钥 |
| `evidenceFiles` | 证明材料 | 文件类型、数量和大小限制由双方统一 |

接口不包含`organization`和`applicationType`字段，数据库也不增加对应的单位和申请类型字段。证明材料统一关联到用户提交的申请记录。

用户编号从登录会话中取得。前端提交的用户编号不能作为后端判断归属的依据。

### 5.2 返回格式与联调约定

普通JSON接口统一返回如下结构；证书和材料下载直接返回文件内容：

```json
{
  "code": "SUCCESS",
  "message": "申请提交成功",
  "data": {
    "applicationId": "42",
    "status": "PENDING"
  }
}
```

- ID、证书序列号统一按字符串返回，避免前端数字精度问题。
- 时间统一返回带时区的ISO 8601格式，页面按北京时间显示。
- 使用HTTP状态码表达未登录、无权限、参数错误及状态冲突等情况。
- 修改数据的请求携带CSRF令牌；登录和退出同样遵循相关配置。
- 开发时由Vite代理`/api`到后端，前后端共同检查会话Cookie和CSRF处理。
- 前端可以先使用模拟数据开发，后端提供真实返回样例后逐项替换。

## 6 数据库与状态约定

### 6.1 主要数据表

| 表名 | 保存内容 | 主要关联 |
| --- | --- | --- |
| `users` | 用户账号、密码哈希、角色和创建时间 | 一个用户可有多个申请 |
| `applications` | 申请信息、公钥、申请状态和审核记录 | 关联用户、材料和证书 |
| `evidence_files` | 加密材料名称和内容、类型及大小 | 关联申请 |
| `certificates` | 序列号、申请编号、证书内容、有效期及吊销状态 | 关联申请和用户 |
| `revocation_requests` | 用户吊销申请、原因和处理情况 | 关联证书和申请人 |
| `system_state` | 存储加密密钥的校验标记 | 用于拒绝错误密钥写入 |
| `operation_logs` | 操作人、操作类型、目标编号和操作时间 | 记录关键管理操作 |

证明材料以加密BLOB保存在SQLite数据库中，通过受权限保护的接口下载。证书以DER数据保存在数据库中；吊销时间和加密后的原因记录在`certificates`表，操作人和操作时间保存在审计日志中。

### 6.2 状态约定

申请状态：

```text
PENDING（待审核）→ APPROVED（审核通过且签发成功）
PENDING（待审核）→ REJECTED（审核驳回）
```

证书展示状态：

```text
VALID（列表中表示在有效期内且未吊销）
REVOKED（已有吊销记录）
EXPIRED（超过有效期且未吊销）
NOT_YET_VALID（尚未到生效时间且未吊销）
```

证书列表状态根据数据库记录和当前时间计算；验证接口另外检查签名、证书内容、有效期和吊销状态。系统无法识别的证书返回未知，不能直接判为有效。

## 8 联调与验收场景

以下是计划执行的检查场景，不代表目前已经实现或测试通过。

| 编号 | 场景 | 预期结果 | 牵头人 |
| --- | --- | --- | --- |
| T01 | 用户生成密钥对并保存私钥文件 | 浏览器生成成功，私钥加密文件可保存，网络请求不包含私钥 | 前端 |
| T02 | 提交有效信息、公钥和证明材料 | 后端形成申请和材料记录，页面显示待审核 | 共同 |
| T03 | 提交空字段、损坏公钥或超限材料 | 后端拒绝，前端显示可理解的原因 | 共同 |
| T04 | 用户尝试查看他人申请、材料或证书 | 后端拒绝访问 | 后端 |
| T05 | 管理员审核通过 | 生成唯一证书，证书公钥与申请公钥一致 | 后端 |
| T06 | 用户下载并验证证书 | CA签名验证成功，有效期和系统状态显示正确 | 共同 |
| T07 | 管理员驳回申请 | 记录驳回意见，不生成证书 | 共同 |
| T08 | 重复点击审核通过 | 不重复生成证书，不破坏申请状态 | 后端 |
| T09 | 用户申请吊销，管理员执行吊销 | 保留吊销记录，再次验证时显示已吊销 | 共同 |
| T10 | 上传被修改或不受信任的证书 | 验证失败或显示不受本CA信任，不显示为有效 | 后端 |
| T11 | 重启系统 | 用户、申请、证书和吊销记录仍然可用 | 后端 |
| T12 | 按运行说明在另一目录或电脑启动 | 能加载依赖、初始化数据并完成主要演示流程 | 共同 |

## 9 报告与答辩分工

课程要求每位同学分别提交报告和源代码。报告模板要求报告内容不少于15页，报告重点体现本人实际完成的工作，组内报告内容应有明确区别。

| 报告内容 | 前端负责人重点 | 后端负责人重点 |
| --- | --- | --- |
| 课题内容与需求 | 用户操作场景、页面需求和交互要求 | 业务规则、数据处理和证书管理要求 |
| 总体设计 | 页面结构、路由、交互流程、接口调用关系 | 系统结构、数据库ER图、模块关系和状态设计 |
| 详细设计 | 表单、文件上传、浏览器密钥生成与私钥保存 | 申请审核、证书签发、吊销、权限和数据访问 |
| 核心代码 | 密钥生成、私钥加密、上传下载与接口请求 | X.509签发、签名验证、状态处理与数据库事务 |
| 测试分析 | 页面操作、表单校验、用户端完整流程 | 接口权限、异常输入、证书与吊销结果 |
| 问题与总结 | 页面交互、浏览器API和联调问题 | 编码格式、证书构造、状态一致性与权限问题 |

两人都应能说明完整业务流程。答辩时，前端负责人重点演示用户操作和管理员页面；后端负责人重点解释数据库、CA签名、证书验证与吊销原理。

## 10 最终交付清单

- 前端与后端完整源代码，以及固定依赖版本的配置文件。
- 数据库建表和初始化脚本、演示账号说明。
- 可运行的软件或构建启动步骤。
- CA初始化和密钥库配置说明，演示密钥与其他环境密钥区分管理。
- 虚构或脱敏的演示材料、示例申请和示例证书。
- 测试场景记录、主要结果截图和问题解决记录。
- 每位同学各自的课程设计报告。
- 按课程要求另行整理的实验课程结果附件。

运行说明应写清软件环境、依赖安装、启动方式、访问地址、演示账号、数据目录和完整操作步骤。
