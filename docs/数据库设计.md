# 后端数据库设计

后端启动时通过`backend/src/main/resources/db/schema.sql`创建所需表和索引。数据库为SQLite，默认位于`backend/data/ca-system.db`；连接启用外键，连接池大小为1。

| 表 | 内容 | 主要约束 |
| --- | --- | --- |
| `system_state` | 存储加密密钥的校验标记 | 用于拒绝错误密钥写入；不保存明文密钥 |
| `users` | 用户名、BCrypt密码哈希、角色、创建时间 | 用户名唯一，角色为USER或ADMIN |
| `applications` | 申请者、加密后的姓名和邮箱、公钥、状态及审核信息 | 关联用户；审核状态受约束 |
| `evidence_files` | 加密后的文件名与文件内容、类型和大小 | 关联申请；材料以加密BLOB存入数据库 |
| `certificates` | 序列号、用户及申请、DER证书、有效期、加密的吊销原因和时间 | 序列号唯一，同一申请最多一张证书 |
| `revocation_requests` | 加密的申请原因、提交人与处理状态 | 同一证书最多一条待处理申请 |
| `operation_logs` | 操作人、操作类型、目标及时间 | 审计申请、审核和证书吊销 |

姓名、邮箱、材料文件名、材料内容、审核意见及吊销原因使用AES-256-GCM加密，每个值使用独立随机nonce。用户名、公钥、状态、时间和证书是管理所需的明文元数据；密码保存为BCrypt哈希。密钥校验标记和受认证的密文可检测错误密钥或内容被修改。

审核通过、证书插入和申请状态更新在一个数据库事务中完成；申请提交和材料保存也在一个事务中完成。CA私钥不在数据库中，保存在数据目录中的PKCS#12密钥库内，受`CA_KEYSTORE_PASSWORD`保护。

已签发证书的吊销时间与原因保存在`certificates`中，关键操作同时写入`operation_logs`。证书自身文件不会因吊销而改变；系统验证时额外检查本地吊销记录。

请妥善备份数据库、`ca-root.p12`、`CA_STORAGE_KEY`和`CA_KEYSTORE_PASSWORD`。存储密钥丢失无法解密材料；已签发证书存在时，如果CA密钥库缺失，系统会拒绝重新创建根CA。
