## 1 接口总览：共 20 个，全部以 `/api` 开头

统一响应包：`{ "code": "SUCCESS", "message": "...", "data": ... }`；文件下载类接口直接返回二进制流，**不套 JSON**。

### 1.1 服务与认证（6 个）

| # | 方法 | 路径 | 权限 | 请求要点 | 响应 `data` |
| --- | --- | --- | --- | --- | --- |
| 1 | GET | `/api/health` | 公开 | — | `{ status: "UP" }` |
| 2 | GET | `/api/auth/csrf` | 公开 | — | `{ headerName, token }`，并下发 `XSRF-TOKEN` Cookie |
| 3 | POST | `/api/auth/register` | 公开 | JSON `{ username, password }`；用户名 3–32 位 `[A-Za-z0-9._-]`，密码 ≥12 字符且 ≤72 字节 | `AccountView { id, username, role }` |

| # | 方法 | 路径 | 权限 | 请求要点 | 响应 `data` |
| --- | --- | --- | --- | --- | --- |

## 2 前端必须实现的三个公共机制

### 2.1 CSRF + Session

1. 任何 POST 之前先 `GET /api/auth/csrf` 拿到 `XSRF-TOKEN` Cookie。
2. 登录成功、退出成功后服务器会**清空 CSRF Cookie**，必须重新 `GET /api/auth/csrf`。
3. 所有请求带 `withCredentials: true`（`frontend/src/api/http.js` 已配置）。
4. axios 默认 `xsrfCookieName = 'XSRF-TOKEN'`、`xsrfHeaderName = 'X-XSRF-TOKEN'`，开发环境经 Vite 代理为同源，可自动带上头；但**首次获取与登录后重新获取必须显式调用**。
5. 收到 `403` 时应重新获取 CSRF 并重试一次；收到 `401` 时清空本地用户态并跳登录页。

### 2.2 错误码处理

`400` 参数错误 / `401` 未登录 / `403` 无权限或 CSRF 失效 / `404` 不存在或无权查看 / `405` 方法不支持 / `409` 业务冲突（重复审核、重复吊销）/ `413` 文件超限 / `415` 类型不支持 / `503` 服务配置或密钥不可用。前端应把 `message` 直接作为提示文案。

### 2.3 文件下载

证书下载、材料下载、根 CA 下载都是二进制流，必须用 `responseType: 'blob'`，再用 `URL.createObjectURL` + `<a download>` 触发保存；材料预览（PDF/图片）同样用 blob URL，**不能用 `<img src="/api/...">` 直连**（会丢失权限头与错误处理）。

## 4 接口层的缺口（前端需规避或双方补做）

| 编号 | 缺口 | 影响 | 建议 |
| --- | --- | --- | --- |
| G1 | 列表接口**不返回 total**，只有 `limit/offset` | 无法做 `el-pagination` 的总页数 | 改为「加载更多 / 上一页下一页」；或后端补 `{ items, total }` |
| G2 | **无操作日志查询接口**（`operation_logs` 表只写不读，对应 F10） | 管理员无法在页面查看审计记录 | 后端补 `GET /api/admin/logs`，或明确该项只在报告中体现 |
| G3 | `GET /api/admin/certificates` **无 status 筛选** | 管理员证书页只能前端过滤或翻页 | 后端补 `status` 参数 |
| G4 | 证书视图**不含申请人姓名/邮箱**，只有 `userId` | 管理员证书列表无法直接显示是谁的证书 | 前端二次查 `/applications/{applicationId}`，或后端补字段 |
| G5 | 用户端申请与证书**需分两次请求**（`/applications/mine` + `/certificates/mine`） | 首页概览要并行两个请求 | 前端 `Promise.all` |
| G6 | 材料下载只给 **材料 ID**，申请详情里才有材料列表 | 需从 `ApplicationView.evidenceFiles[].id` 取 | 正常，注意别把申请 ID 当材料 ID |
| G7 | 无验证码、无改密、无个人信息接口 | 无需对应页面 | 明确不做 |
| G8 | 验证接口**要求登录** | 未登录用户无法自助验证 | 文档写明「已登录用户」即可 |

### 需要注意的实现细节

1. **私钥绝不上送**：`utils/crypto.js` 只把公钥 PEM 放进 `publicKeyPem`，私钥加密文件纯前端下载；浏览器密钥 API 需要 `localhost` 或 HTTPS。
2. **Element Plus 尚未全局注册**：`main.js` 只 `use(router)`，`HomeView` 是按需 `import { ElButton }` + `import '.../button/style/css'`。要么全局 `app.use(ElementPlus)` 并引入 `element-plus/dist/index.css`，要么延续按需导入，两者不要混用导致样式缺失。
3. **无 Pinia 依赖**：如需集中状态，要么在 `package.json` 加 `pinia`，要么用 `reactive` 单例模块（`utils/session.js`）——后者不用改依赖，课程设计足够。
4. **审核与吊销的并发冲突**：`409` 必须给出明确文案（「该申请已审核」「证书已吊销」），并刷新列表。
5. **吊销状态 `PENDING`/`COMPLETED`**：用户侧提交后显示「待处理」，管理员吊销后该申请自动变 `COMPLETED`，页面需体现这条链路。
6. **时间显示**：后端返回带时区 ISO 8601，页面统一转北京时间 `YYYY-MM-DD HH:mm`。
7. **ID 与序列号都是字符串**，不要做数字运算；序列号在路径里大小写均可。

## 7 建议的开发顺序（对齐 `分工方案.md` §7）

1. **基础设施**：`http.js` 拦截器 + `api/auth.js` + `utils/session.js` + 路由守卫 + Element Plus 全局注册。
2. **P1/P2 登录注册**：先打通 CSRF + Session + 角色跳转（后续所有页面的前置）。
3. **P3 工作台 + P5 新建申请**（含 `utils/crypto.js` 密钥生成与私钥加密）。
4. **P4/P6 申请列表与详情**（含材料预览下载）。
5. **P10 审核管理**（打通「审核通过 → 证书签发」）。
6. **P7/P8 我的证书 + 下载 + 吊销申请**。
7. **P11 管理员证书管理 + 执行吊销**。
8. **P9 证书验证**（最后接入，依赖前面全部数据）。
