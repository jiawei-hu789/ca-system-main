# CA系统后端接口约定

本文记录当前后端实际实现的接口，供前端开发和Apifox联调使用。可将同目录下的[openapi.yaml](openapi.yaml)导入Apifox。所有路径以`/api`开头；开发环境通过Vite代理访问同源接口。

## 通用约定

- 普通JSON响应格式为`{ "code": "SUCCESS", "message": "说明", "data": ... }`。错误的`data`为`null`；证书和材料下载直接返回文件。
- ID和证书序列号是字符串；时间是带时区的ISO 8601字符串。列表默认`limit=20&offset=0`，`limit`范围1至100，`offset`不能为负数。
- 状态码：参数错误400、未登录或账号密码错误401、无权限或CSRF错误403、不存在或无权查看的资源404、方法不支持405、业务冲突409、文件超限413、内容类型不支持415、服务配置或密钥不可用503。
- 普通用户只能查看自己的申请、材料和证书；`/api/admin/**`仅管理员可访问。
- 使用Cookie Session。前端开发环境调用同源`/api`；通过Apifox测试时需要在同一会话中保留Cookie。

## CSRF与登录流程

所有POST请求，包括注册和登录，都需要CSRF令牌。

1. 调用`GET /api/auth/csrf`，从响应中取`data.token`，保存返回的`XSRF-TOKEN` Cookie。
2. 后续POST保留Cookie，并在`X-XSRF-TOKEN`请求头中携带`data.token`。
3. 成功登录后服务器清除旧的CSRF Cookie并创建或更新登录会话；再次调用`GET /api/auth/csrf`取得新的Cookie和令牌。
4. 调用需要登录的接口时保留`JSESSIONID`。退出登录也需要CSRF令牌，成功后会话失效。
5. 登录或退出后如需继续提交请求，重新获取CSRF令牌。

`GET /api/auth/csrf`响应示例（令牌值是示意）：

```json
{
  "code": "SUCCESS",
  "message": "CSRF令牌",
  "data": { "headerName": "X-XSRF-TOKEN", "token": "令牌值" }
}
```

## 用户与会话

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/health` | 公开 | 服务存活；不检查数据库和证书 |
| GET | `/api/auth/csrf` | 公开 | 获取CSRF Cookie及令牌 |
| POST | `/api/auth/register` | 公开 | 创建普通用户，不能自行选择管理员角色 |
| POST | `/api/auth/login` | 公开 | 登录并创建会话 |
| POST | `/api/auth/logout` | 已登录或已有会话 | 清除会话与CSRF Cookie |
| GET | `/api/auth/me` | 已登录 | 查询当前用户ID、用户名和角色 |

注册与登录请求体：

```json
{
  "username": "alice",
  "password": "ExamplePass123!"
}
```

用户名为3至32位字母、数字、点、下划线或连字符；密码至少12个字符，UTF-8编码不超过72字节。注册和登录成功时，`data`为：

```json
{ "id": "1", "username": "alice", "role": "USER" }
```

角色为`USER`或`ADMIN`。管理员由首次启动时的环境变量创建，公开注册接口只创建普通用户。

## 认证申请与材料

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| POST | `/api/applications` | 普通用户 | 创建申请并上传材料 |
| GET | `/api/applications/mine` | 已登录 | 查询本人申请 |
| GET | `/api/applications/{id}` | 本人或管理员 | 申请详情 |
| GET | `/api/evidence/{id}/download` | 本人或管理员 | 下载证明材料 |
| GET | `/api/admin/applications` | 管理员 | 查询申请；可传`status` |
| POST | `/api/admin/applications/{id}/review` | 管理员 | 审核并在通过时签发证书 |

提交申请使用`multipart/form-data`：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `applicantName` | 文本 | 必填，1至100个字符 |
| `email` | 文本 | 必填，邮箱格式，最多254个字符 |
| `publicKeyPem` | 文本 | PEM编码的SPKI RSA公钥，2048至4096位，最多8192字符 |
| `evidenceFiles` | 文件，可重复 | 1至3份PDF、PNG或JPEG；每份不超过5MB；文件名不超过128字符，检查扩展名及文件头 |

用户私钥和私钥口令不发送给后端。申请人信息、材料文件名和材料内容在数据库中使用AES-GCM加密保存。材料下载以附件形式返回。

申请响应的`data`结构：

```json
{
  "id": "1",
  "userId": "2",
  "applicantName": "张三",
  "email": "example@example.com",
  "publicKeyPem": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----",
  "status": "PENDING",
  "createdAt": "2026-10-27T00:00:00Z",
  "reviewedAt": null,
  "reviewComment": null,
  "evidenceFiles": [
    { "id": "1", "filename": "proof.pdf", "contentType": "application/pdf", "sizeBytes": 123 }
  ]
}
```

申请状态：`PENDING`待审核、`APPROVED`已通过且证书已签发、`REJECTED`已驳回。管理员列表的可选`status`只接受这三个值；`limit`和`offset`采用通用分页规则。

审核请求体：

```json
{ "decision": "APPROVE", "comment": "材料核对通过" }
```

`decision`为`APPROVE`或`REJECT`；驳回必须填写`comment`，审核意见最长1000字符。重复审核返回409。签发失败时申请状态和证书记录一同回滚。

## 证书与吊销

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/certificates/mine` | 已登录 | 本人证书列表 |
| GET | `/api/certificates/{serial}` | 本人或管理员 | 查询证书详情 |
| GET | `/api/certificates/{serial}/download` | 本人或管理员 | 下载PEM证书 |
| GET | `/api/ca/certificate` | 已登录 | 下载本系统根CA的PEM证书 |
| POST | `/api/certificates/{serial}/revocation-requests` | 证书所属用户 | 提交吊销申请 |
| GET | `/api/admin/certificates` | 管理员 | 证书列表及每张证书的吊销申请 |
| POST | `/api/admin/certificates/{serial}/revoke` | 管理员 | 执行吊销 |
| POST | `/api/certificates/verify` | 已登录 | 上传单张证书并验证 |

证书列表及详情`data`中的对象字段：

```json
{
  "serial": "7a12...",
  "applicationId": "1",
  "userId": "2",
  "issuedAt": "2026-10-27T00:00:00Z",
  "notBefore": "2026-10-26T23:59:00Z",
  "notAfter": "2027-10-27T00:00:00Z",
  "status": "VALID",
  "revokedAt": null,
  "revocationReason": null,
  "revocationRequests": []
}
```

`status`为`VALID`、`REVOKED`、`EXPIRED`或`NOT_YET_VALID`。列表和详情中的状态依据数据库记录与当前时间计算；需要验证签名和证书内容时调用验证接口。序列号为十六进制字符串，路径可使用大小写。

提交吊销申请和管理员执行吊销均使用：

```json
{ "reason": "用户私钥丢失" }
```

`reason`必填、最多500字符。用户对同一证书只能保留一条待处理申请；管理员吊销后，该申请变为`COMPLETED`。对已吊销证书重复操作返回409。吊销原因和申请原因加密保存。

## 验证证书

`POST /api/certificates/verify`使用`multipart/form-data`，文件字段名为`certificate`，支持单张PEM或DER格式X.509证书，最大64KB。

```json
{
  "code": "SUCCESS",
  "message": "验证完成",
  "data": {
    "serial": "7a12...",
    "signatureValid": true,
    "trustedIssuer": true,
    "periodValid": true,
    "revocationStatus": "GOOD",
    "certificateMatchesRecord": true,
    "valid": true,
    "fingerprintSha256": "证书DER的SHA-256十六进制摘要"
  }
}
```

`revocationStatus`为`GOOD`、`REVOKED`或`UNKNOWN`。只有本CA签名与颁发者匹配、证书处于有效期、与数据库中已签发证书完全一致且没有吊销记录时，`valid`才为`true`。未知证书不会显示有效。

本版本通过系统内记录检查吊销状态，尚未发布CRL或OCSP，也没有自动核验申请人是否持有私钥；证件审核由管理员人工完成。
