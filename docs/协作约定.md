# 两人协作约定

## 修改范围

- 前端负责人维护`frontend/`，包括用户端、管理员端页面及浏览器密钥处理。
- 后端负责人维护`backend/`，包括接口、存储、权限、证书与吊销逻辑。
- `docs/`中的接口、状态和数据库约定由两人共同确认。
- 修改对方目录前先沟通。接口路径和字段变化同步文档，避免一方按旧接口开发。

## Git工作方式

从最新`main`创建短期功能分支，例如`feat/application-form`或`feat/certificate-issue`。完成可独立检查的功能后，推送分支并发起Pull Request；合并前说明完成内容、运行方式和已检查情况。

```bash
git switch main
git pull --ff-only
git switch -c feat/application-form
```

提交前使用`git status`和`git diff`核对内容，确认依赖锁文件和文档是否需要更新。前端成员运行前端构建，后端成员完成相应编译和功能检查，联调由两人一起完成。

## 不进入仓库的内容

私钥、CA密钥库、密码、真实身份材料、本地运行数据库、依赖目录和构建产物已通过`.gitignore`排除。新增加的敏感文件格式仍需检查忽略规则。测试采用虚构或脱敏材料。

## 首次开发顺序

当前后端已实现主要接口，前端页面与浏览器端密钥流程仍待开发；以下顺序用于联调和验收。

1. 两人分别启动前后端，在首页检查服务连接。
2. 确认分工、申请字段、接口返回结构和状态定义。
3. 后端实现登录与权限，前端接入会话及CSRF处理。
4. 打通申请、证明材料上传和管理员审核。
5. 接入证书签发、下载、验证和吊销。
6. 整理各自的核心代码、流程图和测试结果，完成独立报告与共同演示。
